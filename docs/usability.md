# Beginner usability review

Core task: enter product cost, understand likely earnings. Default view has selling price and product cost, one calculate action and expandable optional costs/fees. Results precede the accounting breakdown. Plain-language labels explain margin, break-even, ad budget and ROI. Zero is allowed deliberately; missing and malformed money fields are rejected. Costs above price trigger a caution without preventing valid loss scenarios.

Persona review (design inspection, **not user evidence**):

| Persona | Accommodation | Remaining evidence |
|---|---|---|
| Complete beginner | Two main inputs, explanations, textual outcome | First fee review is more involved than ideal; category choice and eligibility review still need user testing. |
| Older/nontechnical | Large labeled controls, consistent product-cost language | Real installation/readability trials. |
| Screen reader | Semantic HTML, announcements, focus and table headers | VoiceOver trial. |
| Keyboard only | Native controls, visible focus, skip link | Native side-panel and full data-control manual trial. |
| Low vision | Larger text, reflow, restrained contrast | Actual Chrome zoom and user evaluation. |
| Experienced seller | Breakdown, promotion, target, ad budget, ROI | Independent MDV/Live caps provided; arbitrary program rows/multiple profiles later. |

Recruit a mixed group including Shopee sellers, older adults, novices and people using accessibility features. Obtain consent without collecting unnecessary personal or financial data. Record anonymous task timings, task completion, critical errors and qualitative confusion, not credentials or browser history.

Tasks: install unaided; calculate within 30 seconds of opening a supported product; identify the result state within 5 seconds; find/open breakdown without a manual; use keyboard; export/delete defaults. Aim for ≥95% task completion, <1% critical errors, <5% needing basic documentation. These are goals, **not measured achievements**. Small formative samples cannot establish population-level percentages; document sample size and uncertainty.

First-use category selection and account/program review are needed to avoid incorrect universal defaults. Standard presets reduce fee entry, but account eligibility cannot be determined from a public product page. Real testing is required before claiming the ideal one-input beginner workflow. Public installation cannot be tested until a store distribution exists.
