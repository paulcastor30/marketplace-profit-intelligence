# Publication checklist — do not submit until complete

- [ ] Complete category/account/program evidence and decide approved manual-assumption scope.
- [ ] Compare actual seller settlement rounding and category boundary cases.
- [ ] Demonstrate supported live product variants and safe failures.
- [ ] Complete native-panel keyboard and actual 200% zoom QA.
- [ ] Complete VoiceOver and representative-user trials; fix release-blocking defects.
- [ ] Record task success/timing evidence with sample size and limitations.
- [ ] Finalize original branding, trademark/domain checks and extension name.
- [ ] Choose GitHub owner, create public GPL repository and set support/security contacts.
- [ ] Configure optional confirmed Ko-fi/Sponsors handles (not required for core function).
- [ ] Publish reachable privacy policy, support page and optional product website using a provider whose current terms permit commercial use.
- [ ] Register Chrome developer account and verify any one-time fee.
- [ ] Recheck current store policies and data-disclosure questions.
- [ ] Complete/approve release-gate.json with evidence references.
- [ ] Run CI, audit and release package check; review ZIP contents and hash.
- [ ] Review screenshots, descriptions, geographic coverage and disclaimers.
- [ ] Submit manually to Chrome Web Store; record review outcome and resulting installation URL.
